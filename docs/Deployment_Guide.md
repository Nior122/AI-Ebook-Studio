# Deployment Guide — Cloudflare Pages (frontend) + Render (backend) + Neon (DB)

This guide covers the recommended production setup. The frontend runs on
**Cloudflare Pages** (Next.js via `@opennextjs/cloudflare`), the backend on
**Render** (FastAPI as an always-on web service), and the database on
**Neon.tech** (serverless Postgres).

Why this split: the backend runs background jobs and a WebSocket event bus
in-process, so it needs an always-on single instance — Render gives you that;
Cloudflare Functions would kill long jobs (see `docs/Studio_UX.md`).

---

## 1. Database — Neon.tech

1. Create a project on https://neon.tech and grab the connection string.
2. **Use the "Connection string (Non-pooling)" variant.** asyncpg (the SQLAlchemy
   async driver) cannot use Neon's PgBouncer pooled endpoint reliably.
3. Format the DSN for this app:

   ```env
   DATABASE_URL=postgresql+asyncpg://USER:PASSWORD@ep-xxxx-xxxx.REGION.aws.neon.tech/ebook_studio?sslmode=require
   ```

4. Run the migrations once (locally or from a one-off Render shell):

   ```bash
   cd backend && pip install -r requirements.txt
   DATABASE_URL="postgresql+asyncpg://..." alembic upgrade head
   ```

   This creates all tables, including the Studio UX tables
   (`studio_activities`, `studio_notifications`, `studio_versions`,
   `studio_bookmarks`) and the `projects.stage` column.

## 2. Backend — Render

1. Push this repo to GitHub.
2. Render dashboard → **New → Blueprint** → select the repo.
   The `render.yaml` at the repo root defines the `ai-ebook-studio-api` service
   (rootDir `backend`, `uvicorn app.main:app --port $PORT`).
3. In the service's **Environment** tab set the `sync: false` variables:
   - `DATABASE_URL` (Neon DSN above)
   - `CLERK_PUBLISHABLE_KEY`, `CLERK_SECRET_KEY`, `CLERK_JWKS_URL`
   - AI provider keys you want to use (`OPENAI_API_KEY`, `ANTHROPIC_API_KEY`,
     `OPENROUTER_API_KEY`, `GROQ_API_KEY`, …) — optional, the local engine works
     without any
   - `SMTP_HOST/USER/PASSWORD` (for real password-reset/verification emails)
   - `LIBRETRANSLATE_URL` if you self-host a LibreTranslate server
4. `SECRET_KEY` and `JWT_SECRET` are auto-generated by the blueprint.
5. Keep it a **single instance** — the job queue and event bus are in-process.

## 3. Frontend — Cloudflare Pages

1. In the Cloudflare dashboard: **Workers & Pages → Create → Pages →
   Connect to Git** → pick the repo.
2. Framework preset: **Next.js**. Build settings:
   - Build command: `npm run build`
   - Build output directory: `.open-next`
   (this matches `frontend/wrangler.toml` → `pages_build_output_dir`)
3. Environment variables (Settings → Environment variables, set for
   Production + Preview):
   - `NEXT_PUBLIC_API_BASE_URL` → `https://<your-backend>.onrender.com/api/v1`
   - `NEXT_PUBLIC_CLERK_PUBLISHABLE_KEY`
   - `CLERK_SECRET_KEY` (used by middleware/server code)
4. CORS: the backend's `CORS_ORIGINS` must include your Pages domain
   (`https://<project>.pages.dev`).

### Local Cloudflare preview (optional)

```bash
cd frontend
npm install
npm run preview        # builds with OpenNext + serves on the Workers runtime
npm run deploy         # deploys to Cloudflare (needs CLOUDFLARE_API_TOKEN + CLOUDFLARE_ACCOUNT_ID)
```

## 4. Env vars checklist

See the fully commented template in the root **`.env.example`** — it lists every
variable the backend and frontend read, with placeholders and notes.

## 5. After deploying

- Register a user, create a project, and click **Generate Book** — the local
  engine works with zero API keys, so the whole flow should succeed on day one.
- Add an AI provider key later and generation switches to real LLMs.
- Verify email flows: without SMTP, reset links are written to the Render logs
  (and returned as `dev_link` — only outside `APP_ENV=production`).
